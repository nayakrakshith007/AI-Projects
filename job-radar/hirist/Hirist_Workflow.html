Hirist workflow (tech roles)

Reads Hirist with two methods at once and compares them: its free-text search (the page loads its jobs as JSON, which is read) and its own tag pages (HTML cards). Hirist filters by date on its own server, so only a few pages per keyword are read. A pool of Chromes with a fresh browser state shares one queue of pages. Click any node for the technical detail.

1. The input you give it

The shared file job-radar-V3/input.csv. Only tech roles run (Experience above 0).

Role,Keywords,Experience,Location
AI Engineer,"AI Engineer;LLM Engineer",5,India
  • Keywords are searched with the search method as they are. For the tag method they are mapped to Hirist tags in hirist/tags.csv (- = no tag page).
  • Experience: Hirist gives a numeric range, so the rule is exact: a job stays if its maximum reaches the minimum or it states none.
  • Command line: --role, --hours N (default automatic, at most 168 h = 7 days), --method both|search|tag, --workers N.

4. The two methods, compared on the first run

  • Scored against the old project's validated role title patterns: search found 243 role-matching jobs (90% recall, 54% precision), tag found 248 (92% recall, 68% precision), 223 by both.
  • Each also finds jobs the other misses: 23 relevant jobs only the tag method found (for example "Vice President - Data Science", "Research Scientist"), 18 only the search method found (13 of them Architect jobs, because Hirist has no Solutions Architect tag).
  • Tag pages cover the roles that have a tag; search covers every keyword but is looser (it also returns many unrelated jobs).
  • Recommendation: run both and keep the union. It costs about 6 minutes, and the "Found by" column keeps track of which method found each job.

5. What a real run gave (2026-10-11, 7-day window)

  • 8 tech roles, 14 keywords, 22 lists. 4 Chromes read 103 pages and 1,875 jobs in 6.3 minutes (25 to 27 pages each). No human check.
  • 417 unique jobs kept: 178 found by both methods, 150 only by search, 89 only by tag. Dropped: 35 by the experience rule.
  • 200 are in Bengaluru, 62 show a salary, 328 have the exact posting time, 33 are work-from-home. Posted dates run from 2026-10-05 to 2026-10-11.
  • About half (202 of 417) match a role title pattern; the rest are loose matches that the combined pipeline will filter by title.

6. Not in this workflow (done later, in the combined pipeline)
